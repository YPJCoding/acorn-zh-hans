## 待审条目的状态规则

目前 `pending.json` 仅表示尚未匹配，不能作为已完成的人工分类。逐条审阅后区分：

- **待翻译**：实际 UI 文本或错误提示。
- **无需翻译**：格式名、API 名、标准名称、占位符、用户文件名。
- **疑似遗留/调试**：留原文，不能未经确认删键。
- **上下文待确认**：先找到对应界面再译。
- **资源无法生效**：运行时仍为英文，转到遗漏调查清单。

## 分模块工作顺序与验收

1. **设置 / 新建 / 打开 / 保存**：逐个设置页、新建图像参数、保存警告。
2. **工具 / 选区 / 图层**：每种工具面板、图层右键菜单、蒙版、组、锁定状态。
3. **文字 / 形状 / 色彩**：字体、路径文字、对齐、布尔运算、颜色管理和不同位深。
4. **滤镜 / RAW / 导出**：滤镜分类和参数、RAW 面板、每种导出格式专属设置。
5. **自动化 / 错误提示 / 帮助入口**：批处理、脚本、权限不足、保存失败、缺失资源。

每个模块记录：源版本、测试窗口、触发方式、语言生效情况、截断/布局、语义校对、操作结果。没有实际触发的条目不能标记 UI 已验证。使用专用生成的测试文件；不上传或修改用户原图。

## 遗漏调查

- 扫描编译 nib 和可执行文件只能得到候选文本，不能直接作为确定的翻译键。
- 利用已授权的 Accessibility 读取目标应用窗口文本，建立实际出现的英文列表。
- 与静态键匹配，补充确实缺失且资源可生效的精确键。例如 `Filter` 顶层菜单不在现有语言表中，本次通过 UI 检查补上。
- 优先以资源补齐；不直接改可执行程序机器码。系统控件、第三方插件、在线帮助另列范围。

## 新版本适配

先 `inspect` 新原版到新的报告目录，再比较新增、删除和改变的键。不能只凭营销版本号沿用验证结论：build 也需核对。重新制作应用副本、检查核心流程后，才把版本/build 纳入已测试集合。
